# Amnezia: российский вход и зарубежный выход

Общайся с пользователем по-русски. Выполняй работу инструментами, а не выдавай пользователю последовательность ручных команд, если доступен терминал с SSH. Вызов скилла для настройки разрешает необходимые установки пакетов и обратимые изменения на указанных VPS. Не запрашивай повторное разрешение на уже согласованную работу. Системные ограничения инструментов и проверки доступа сохраняются.

## Первое действие

1. Определи возможности среды: выполнение команд, доступ к локальным файлам и исходящий SSH. Не выдавай наличие скилла за наличие удалённого доступа.
2. Если пользователь передал путь к конфигурации, используй его. Если пути нет, спроси один раз: «Укажи путь к `servers.private.json`; если файла нет, я создам шаблон в локальной папке вне облачной синхронизации». Если доступен терминал, сразу создай шаблон командой `python scripts/control.py init --dir <локальная-папка>/VPN-Automation` и сообщи путь. Не проси вставлять пароли в чат.
3. Прочти [формат входных данных](references/input.md) и [порядок настройки](references/runbook.md). До изменения серверов выполни `control.py validate --config <путь>`. Эта команда не печатает пароли.
4. Если нет терминала/сети, честно сообщи конкретное ограничение и предложи перенести этот же комплект в агент с SSH. Не начинай бесконечный диалог «выполни ещё одну команду» под видом автоматизации.

## Секреты и подключения

- Доступы находятся только в отдельной папке запуска, НЕ внутри скилла. Читай их программно через helper или эквивалентный SSH API; не выводи файл целиком инструментами в чат.
- Поддерживаются пароль и SSH-ключ. Пароль и passphrase нельзя помещать в аргументы процесса, shell history, отчёт, git, архив скилла или URL. Приватные WireGuard-ключи генерируй на VPS; наружу для соединения передавай только публичные.
- Helper `scripts/control.py` использует Paramiko и проверяет ключ сервера по заранее доверенному SHA256 fingerprint либо `~/.ssh/known_hosts`. `scan` только показывает неподтверждённый fingerprint. Не принимай его автоматически как доверенный: сравни с консолью провайдера/доверенным known_hosts; при отсутствии независимого источника спроси пользователя один раз о доверии.
- Не отключай проверку SSH host key, не передавай root-пароли внешним сайтам. Для клиента выдавай индивидуальный VPN-профиль без административных доступов.
- Созданные backup/config/QR содержат секреты: права 0600 на Linux, ограниченный доступ на Windows, никаких публичных ссылок.

## Режимы

- `repair`: сохранить рабочую схему, обследовать, исправить доказанную причину; не переустанавливать контейнер и не менять клиентские ключи.
- `install`: обследовать оба VPS; установить отсутствующие компоненты и настроить схему по runbook. Для AmneziaWG соблюдать реальный формат текущей версии официального клиента. Не подменять AWG обычным WireGuard на участке клиент → RU.
- `audit`: только чтение и отчёт, никаких установок и изменений.
- `backup`: создать и скачать именованные копии, сравнить SHA256; не заявлять о проверенном восстановлении без отдельного теста.
- `restore`: проверить содержимое архива, целевые адреса и конфликты. Восстанавливать в подготовленный/пустой target; не уничтожать живой контейнер без явного разрешения заменить его.

## Автономность и границы

Сам выбирай свободные адреса туннеля, порты, имена managed-файлов и параметры, если они не заданы; фиксируй выбор в несекретном state.json. Не используй исторические IP как новые цели.

Продолжай после обычных обратимых шагов без уточнений. Пауза нужна только для отсутствующих доступов/SSH-доверия, ограничений среды, недоступного провайдерского firewall или действительно разрушительного конфликта. После трёх одинаковых неудачных попыток одного шага останови именно этот шаг, сохрани рабочий доступ и объясни препятствие. Не покупай и не удаляй VPS, не меняй биллинг или аккаунты.

Не выполняй upgrade ОС, массовый flush iptables/ipset, удаление Docker-сетей/volumes или обновление Amnezia в рамках обычной настройки. Firewall должен оставлять административный SSH доступным. При включённом UFW/nftables/firewalld интегрируйся с фактическим backend, а не отключай его.

## Обязательные свойства результата

- Обычный клиентский трафик выходит через RU; заданные сервисы — через зарубежный VPS. Сам VPS сохраняет основной маршрут и SSH через свой публичный интерфейс.
- DNS VPN-клиентов обрабатывается нашим dnsmasq и наполняет ipset до подключения. `resolver.arpa` не пересылается внешнему DNS. Учитывать дополнительные домены Facebook для Instagram.
- У правил маршрутизации есть загрузка после перезапуска и периодическая идемпотентная проверка. Источник DNS через межсерверный туннель не должен терять своё policy rule.
- Нельзя объявлять поддержку IPv6, Android Private DNS или встроенного DoH приложений без фактической проверки. DNS filter-AAAA не равен блокировке всего IPv6.
- После успешных серверных проверок выполни разрешённый reboot test и сделай backup. Если перезагрузка не разрешена, отметь её как непроверенную; не спрашивай о ней бесконечно.
- Тесты приложений требуют доступа к устройству или короткого подтверждения пользователя. HTTP 200/DNS/IP не подтверждают работу авторизации, ленты, видео и сообщений.

## Артефакты

В папке запуска сохраняй: `state.json` (без секретов), `report.md` (что изменено, результаты, ограничения, rollback), `backups/`, `clients/` (ограниченный доступ), `generated/` (проверенные скрипты). В отчёт не включай содержимое key/config, DNS-историю других пользователей и полные packet dumps. В финале укажи реальные выполненные проверки и ссылки на файлы; не обещай доступность при любых блокировках.

Этот пакет — переносимый рабочий скилл для агента, а не уже испытанный на всех провайдерах one-click установщик. Не скрывай непроверенные этапы. Источники и критерии проверки: [references/runbook.md](references/runbook.md).
