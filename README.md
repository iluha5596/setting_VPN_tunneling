# Amnezia: выборочная маршрутизация через два VPS

Переносимый скилл для AI-агента, который помогает настроить и обслуживать личный VPN: российский сервер принимает подключения AmneziaWG, а выбранные сервисы выходят в интернет через зарубежный VPS.

**Это инструкции для агента и SSH-утилита, а не универсальный one-click установщик.** Для самостоятельного выполнения агенту нужны терминал, доступ к локальным файлам, исходящий SSH и разрешение изменять ваши VPS. Загрузка ZIP в обычный чат этих возможностей не добавляет.

## Схема

```text
Телефон / компьютер с AmneziaVPN
              │ AmneziaWG
              ▼
        Российский VPS
              ├── обычный трафик ─────────────► Интернет через RU
              │
              └── выбранные назначения
                        │ WireGuard
                        ▼
                  Зарубежный VPS ────────────► Интернет через EXIT
```

DNS-запросы VPN-клиентов обрабатывает `dnsmasq`. Ответы для выбранных доменов добавляются в `ipset`; правила маршрутизации направляют соответствующие IP через межсерверный туннель.

В runbook предусмотрены ChatGPT, Claude, Gemini, YouTube, Instagram и Telegram. Список можно сократить в плане запуска. Instagram использует также домены Facebook, поэтому часть трафика Facebook будет направляться через зарубежный сервер.

## Быстрый запуск с агентом

1. Скачайте репозиторий. Передайте агенту папку `amnezia-two-hop` или ZIP этой папки. Для встроенной поддержки skills установите её согласно документации используемого приложения; в Codex стандартная пользовательская папка — `~/.codex/skills/`.
2. Отправьте запрос ниже. Агент создаст отдельный локальный файл доступов, если у него есть необходимые инструменты.
3. Заполните файл локально и сообщите агенту **путь**, а не содержимое с паролями.

```text
Используй скилл amnezia-two-hop. Проверь доступность терминала и SSH.
Создай локальную папку VPN-Automation вне облачной синхронизации с
servers.private.json и plan.json. Я заполню доступы локально.
После этого самостоятельно обследуй серверы, выполни настройку,
проверки и резервное копирование по SKILL.md. Не выводи секреты в чат.
Не покупай и не удаляй VPS. Сохраняй работающие конфигурации.
```

Для существующей схемы используйте `mode: repair`, для новых серверов — `install`. Также предусмотрены `audit`, `backup` и `restore`. Режим задаёт инструкции агенту; SSH-helper сам не выполняет весь runbook и не интерпретирует план развёртывания.

Подтверждение доверия к новому SSH-серверу, системные разрешения, импорт VPN на телефон и проверка приложений без доступа к устройству могут требовать участия владельца.

## Создание файла доступов вручную

Нужен Python 3.10 или новее. Для `init` и `validate` сторонние пакеты не требуются. На Windows, если команда `python` недоступна, используйте установленный Python или `py -3`.

PowerShell:

```powershell
python .\amnezia-two-hop\scripts\control.py init --dir "$env:LOCALAPPDATA\VPN-Automation"
notepad "$env:LOCALAPPDATA\VPN-Automation\servers.private.json"
```

Linux / macOS:

```bash
python3 amnezia-two-hop/scripts/control.py init --dir "$HOME/.local/share/vpn-automation"
```

Будут созданы `servers.private.json`, `plan.json` и папки `backups`, `clients`, `generated`. Повторный запуск не перезаписывает существующие доступы. На Windows проверьте права доступа к папке: POSIX-права, заданные Python, не заменяют Windows ACL.

В `servers.private.json` заполните для ролей `ru` и `exit`:

- `host`: IP или DNS-имя сервера без `https://` и `root@`;
- `port`: SSH-порт, обычно `22` — это не UDP-порт VPN;
- `username`: пользователь SSH;
- `auth`: пароль **либо** путь к приватному SSH-ключу с необязательной passphrase;
- `host_key_sha256`: независимо проверенный отпечаток SSH-сервера. Пустое значение требует доверенной записи в локальном `known_hosts`.

Полные примеры обоих способов авторизации: [формат входных данных](amnezia-two-hop/references/input.md). Внутри JSON пути Windows удобнее указывать через `/`. Пароли и пути должны соответствовать синтаксису JSON.

## SSH-helper

Создайте изолированное окружение и установите зависимости:

```bash
python -m venv .venv
```

Далее активируйте окружение способом вашей ОС или вызывайте его Python напрямую:

```text
Windows:      .venv\Scripts\python.exe
Linux/macOS:  .venv/bin/python
```

В активированном окружении:

```bash
python -m pip install -r amnezia-two-hop/scripts/requirements.txt
python amnezia-two-hop/scripts/control.py validate --config /path/to/servers.private.json
```

Команды выполнения проверенного Bash-скрипта и скачивания backup:

```bash
python amnezia-two-hop/scripts/control.py run --config /path/to/servers.private.json --server ru --script /path/to/checked-script.sh
python amnezia-two-hop/scripts/control.py get --config /path/to/servers.private.json --server ru --remote /root/vpn-backups/backup.tar.gz --local /path/to/local/backup.tar.gz
```

`run` действительно выполняет переданный скрипт на сервере. Он не является dry-run. `scan` показывает неподтверждённый fingerprint без авторизации; сравните его с независимым доверенным источником до использования. При SSH timeout удалённый процесс может продолжать работу: сначала выясните состояние, затем решайте, нужен ли повторный запуск.

## Исправления, учтённые в runbook

- Восстановление обоих policy rules, включая маршрут для источника DNS в туннеле.
- Определение Docker-сети по адресам и маршруту, а не по переменному порядку `eth0` / `eth1`.
- Локальная обработка `resolver.arpa`, чтобы DNS-посредник не объявлял внешний encrypted resolver вместо себя.
- Дополнительные домены Facebook, к которым обращается Instagram.
- Проверка после перезагрузки и отказ от постоянного ручного списка отдельных IP.
- Раздельное хранение пользовательских конфигураций и административных backup.

## Проверки и ограничения

Локальные тесты без подключения к настоящим VPS:

```bash
python amnezia-two-hop/scripts/test_control.py -v
```

Проверяются создание шаблона без перезаписи, отклонение неверного host key до авторизации, выполнение скрипта с сохранением exit code и скрытием тестового пароля, а также получение fingerprint без авторизации.

Базовая схема проверялась на Ubuntu 24.04 с AmneziaWG, российским VPS и DigitalOcean AMS3. ChatGPT и Instagram на iPhone работали через Wi-Fi и мобильную сеть, а серверные настройки сохранялись после reboot. **Полное автоматическое развёртывание этим комплектом на чистых VPS, восстановление backup и клиент Android пока не проверены.**

Выборочная маршрутизация основана на IP, а не на идентификации приложения. Общие CDN могут направить через EXIT и посторонние сайты. Встроенный DoH приложений, Android Private DNS и IPv6 требуют отдельной проверки. `filter-AAAA` не блокирует весь IPv6. Работа при любых ограничениях сети и принятие адресов дата-центров внешними сервисами не гарантируются.

## Секреты и резервные копии

Не коммитьте `servers.private.json`, приватные ключи, экспортированные VPN-профили, QR-коды, дампы трафика и архивы backup. `.gitignore` исключает основные такие файлы, но не заменяет проверку содержимого перед commit. Рабочую папку с доступами держите отдельно от репозитория и облачной синхронизации.

Архивы скачиваются с проверкой SHA256. Совпадение хеша подтверждает передачу файла, но не полноту backup и не успешность восстановления.

Официальные источники и процедуры диагностики перечислены в [runbook](amnezia-two-hop/references/runbook.md#8-источники-для-перепроверки-версии).
